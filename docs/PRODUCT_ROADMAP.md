# TurfMate product roadmap

TurfMate is being built in deliberate stages. The customer booking journey is the priority; community, learning and commerce will follow once booking is dependable.

## Website milestones

- [x] v0.1 — visual direction and clickable booking prototype
- [x] v0.2 — repository foundation, responsive page system, venue discovery, saved shortlist, demo checkout and automated smoke checks
- [ ] v0.3 — detailed venue profiles, facilities, photo gallery, policies and improved availability UX
- [ ] v0.4 — production frontend framework, typed data contracts and reusable design system
- [ ] v0.5 — customer authentication and profile
- [ ] v0.6 — turf-owner portal, pitch inventory and operating calendar
- [ ] v0.7 — race-safe booking holds and reservation lifecycle
- [ ] v0.8 — payment-provider integration, webhook verification, refunds and reconciliation
- [ ] v0.9 — admin operations, support tools, monitoring and audit trail
- [ ] v1.0 — pilot with verified partner venues, security review and production readiness

## Later ecosystem modules

1. TurfMate Community — teams, player discovery, invitations and friendly matches.
2. TurfMate Academy — skill paths, drills, fitness and verified coach profiles.
3. TurfMate Tournaments — event discovery, registration, fixtures and results.
4. TurfMate Store — boots, jerseys, footballs and training equipment.

## Release principles

- Sample listings and demo slots must always be clearly labelled until real partner inventory is connected.
- Never collect or pretend to collect payment in the prototype.
- Booking confirmation must be server-authoritative; a browser state or redirect cannot confirm payment.
- Inventory must be shared across online, phone, WhatsApp and walk-in bookings.
- The future Android app must use the same backend and booking rules as the website.
